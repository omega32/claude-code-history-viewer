# Protected Codex prompt state

Promote the proven bounded Codex checkpoint/reference/candidate engine into an explicitly requested production one-shot candidate path. Keep the existing complete normalizer and native source/lineage checks authoritative. Do not add another parser or cleaner, a daemon, Companion dependency, Notifier code/settings, hooks, model turns or provider-store writes.

The existing `--dump-session-prompt-candidates` command accepts one bare, non-repeated `--prompt-state-cache` flag only with `--provider codex`. Its output remains the exact ordinary candidate array, including missing references, duplicate task bindings and sidechain metadata. Unknown, malformed or conflicting options fail before source work. Advertise additive `codex-prompt-state-cache-v1` on Windows; non-Windows Codex requests remain the complete no-cache path. Claude and ordinary dump/snapshot commands retain their contracts.

Use current-user Windows DPAPI with UI forbidden and no machine-wide or prompt flow. All complete engine state, including candidates, checkpoint/inference metadata and original sparse references, exists on disk only inside protected ciphertext. Place a domain/schema/declared-length/SHA-256 envelope inside DPAPI and verify it before strict bounded typed decoding; successful unprotection alone is not sufficient. A public checksum alone is not state authenticity. Protection covers accidental corruption and untrusted requests/file bytes; malicious same-user processes with DPAPI/source access are outside this claim, and DPAPI is not executable attestation.

Derive the expected cache slot from the current executable image SHA-256 and compiled native package version, engine epoch, provider, logical session, canonical selected carrier, canonical Codex home and canonical cache root before loading a saved blob. Bind those values inside the protected envelope as well. Validate all saved counters/positions/candidate-reference consistency before following cursor paths, then run ordinary fresh lineage selection, complete accepted-prefix verification, bounded replay and final confirmation before publishing any cached result. Missing, stale, incompatible, malformed, unprotectable, oversized or uncertain state falls back to the complete authoritative result, never a manufactured pending miss.

The default root is native `cache_dir()/claude-code-history-viewer/codex-prompt-state-v1`. `CCHV_PROMPT_STATE_CACHE_DIR`, read only through `profile_paths::env`, selects an absolute dedicated root for this cache alone; invalid, relative, linked or unavailable roots, and roots overlapping the configured Codex home, bypass caching. No root configuration flag is added. Tests use scoped profiles/overrides; an isolated production CLI benchmark supplies owned `CODEX_HOME` and cache-root environment paths.

Retain at most eight entries with a 24-hour reuse TTL and cap aggregate ciphertext at 128 MiB. The protected update timestamp gates reuse; expired files are removed during subsequent cache maintenance, not by a timer or a guarantee of physical deletion at the 24-hour boundary without another call. A ciphertext file is at most 64 MiB and its protected inner payload at most 48 MiB. Keep existing engine limits of 65,536 normalized positions, 16 MiB reference strings, 2,048 candidates, 32 MiB serialized candidate payload and the native cursor/replay/lineage bounds. Maintenance and enumeration are bounded. A nonblocking exclusive `fs2` directory lock covers load, validation, source proof, replay, ciphertext-only atomic publication and recognized-entry eviction. Contention or maintenance failure uses the full path without a cache write. Never use PID liveness as lock authority, create plaintext state/temp files, repair foreign permissions, or delete unrecognized files.

Make exactly one compatible capability minor transition from 1.31.0 to 1.32.0 through the repository synchronization helper. Required validation includes tests-first negative/positive cache cases, exact ordinary/full-versus-cached parity, two-process new-prompt replay, source rewrite/twin/ambiguity/collision restoration, forged/source-correct plaintext and corrupt protected state, image/profile/path/schema/TTL/budget drift, concurrent lock/publication/eviction and failure fallback; the complete isolated serial Rust gate, both Clippy surfaces and formatting remain mandatory. Whole configured ccmsg acquisition must meet the separately measured at-least-50% new-prompt goal before runtime acceptance; retain exact proof/refusal parity and report cold seed cost separately.
