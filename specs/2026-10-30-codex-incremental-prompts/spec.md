# Codex incremental prompt prototype

Status: historical development slice completed at e646a11. The [production state-cache follow-up](../2026-10-30-codex-prompt-state-cache/spec.md) promotes the shared engine after this acceptance; the finite development probe remains test-only with its original exact libtest name preserved. The original scope and measurements below describe this prototype slice, not a ban on that separately authorized follow-up.

Implement a bounded in-memory Codex-only development prototype that seeds the existing complete provider normalizer once, retains its safe checkpoint, complete structural initiating candidates with original references, and a sparse reversible original-reference ledger for every normalized record carrying a reference. Reuse the existing snapshot/parser state machine and exact accepted-prefix/lineage checks. Do not create another parser, tag cleaner, production command, capability, saved cache, worker, daemon, provider prompt or Notifier integration.

All native code and hooks are compiled only under `cfg(test)`. The probe is one explicitly invoked ignored unit test in the optimized isolated library-test executable, not a default application target or feature. Package version 1.31.0 remains unchanged: this is development-only tooling and specification work, with no shipped runtime behavior change.

Capture original references and candidates at Codex snapshot finalization callsites before irreversible collision clearing. Do not observe unrelated providers. Sparse ledger entries are keyed by raw normalized position; implicit absent entries plus raw count cover unreferenced records. Keep original candidate references so a suffix replacement can remove old contributions and restore a previously colliding reference. Recompute global exact-reference and valid scheme/ID collision effects before selecting candidates. Missing references and duplicate task bindings remain candidates; shared consumer projection owns cleanup and availability/ambiguity decisions.

Any residual user record containing a direct tool-result block makes incremental retention ineligible, even when generic merge preserves vector length. This conservatively proves generic tool merging is a no-op and raw parser/checkpoint coordinates remain valid. Apply only the final returned Full/Replace view after provider proof succeeds; discard intermediate finalization attempts preceding full fallback. Check count, checkpoint and candidate/ledger consistency. State publication is atomic through one mutable engine owner.

Seeded paginated cursors are provisional until a fresh native cursor refresh confirms accepted history. Re-resolve authoritative lineage carrier selection before and after refresh, including plain/compressed twins and duplicate immutable IDs. Never substitute metadata-only freshness for prefix hashes. Rewrite, shrink, selected-path rotation, parser epoch drift, changed selection, missing proof/coverage, unsafe backreferences and uncertain coordinates rebuild or refuse through the authoritative full path. A new asynchronous reply retains the existing full fallback because accepted-prefix verdicts cannot certify a new reply. Bounds or unconfirmed seeds return ordinary full candidates and retain no incremental state; eviction must never manufacture a pending miss.

Initial bounds are 65,536 raw normalized positions, 16 MiB of retained reference strings, 2,048 candidate records and 32 MiB of serialized candidate payload, plus the existing 64 KiB cursor, 64 MiB replay-window and 128-carrier limits. Report serialized/ref accounting separately from transient seed allocations and process RSS. Overflow falls back to full acquisition with no retained state.

The prototype performance gate is at least 50% lower warm native proof/replay/candidate lookup time for a genuinely NEW ordinary prompt on the known approximately 520 MB logical workload. The requested task must be absent at seed, then acquired after appending its actual retained canonical input before completion. Compare exact normalized candidate arrays and existing production TypeScript projection against a fresh complete normalizer at the same fixture boundary. Do not count unchanged lookups, cached same-prompt reads or newly appended asynchronous replies as this speed gate. Record seed cost separately. Persistence or a worker requires a later decision after the gain is proved.

This native component gate informs only whether to pursue a storage/process-lifetime design. It excludes CLI startup, outer session metadata resolution and the parent's carrier/executable-image proofs. A later integrated implementation must separately demonstrate the at-least-50% whole-ccmsg acquisition enablement goal with exact result/refusal parity. No production path is enabled or production latency improvement claimed by this development slice.
