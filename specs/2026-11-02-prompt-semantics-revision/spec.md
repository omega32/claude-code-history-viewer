# Native prompt semantic revision

Add feature `prompt-semantics-revision-v1` and top-level string `prompt_semantics_revision` to `--capabilities` without changing headless API version 1. Its canonical syntax is `^[1-9][0-9]{0,8}$`, initially `"1"`. A single explicit maintainer-owned constant in shared `prompt_candidates.rs` conservatively covers supported Codex and Claude prompt semantics; it is independent of package releases, executable/source hashes, snapshot cursors, metadata caches and persistent-state schemas.

Advance the semantic epoch whenever native changes can alter a prompt outcome, cleanable text, certified record identity, selection or refusal for the same supported source/selector, including authored classification, provider task/prompt binding, sidechains, content normalization, provider-neutral tool merging, reference validation, all-record collisions, candidate multiplicity, source selection/visibility and ordinary/full/cached path behavior. Compatible fixes can require an epoch bump. Unrelated providers, UI, titles/statistics, packaging, storage representation and proven output-equivalent performance/refactoring changes retain it. This declaration does not automatically detect semantic drift and is not executable attestation. Independently advance cursor/cache compatibility versions when their own retained-state rules require it; the semantic epoch neither replaces those versions nor repairs old normalized prefixes.

The coordinator composes SHA-256 of the canonical tuple `['ccmsg-prompt-cleanup-v1', profile, rootMaintainedEpoch, nativeEpoch]` into additive `resolved.options.cleanupRevision`, keeping existing data keys and preserving per-result revisions' existing source/image/version bindings. A legacy base without the feature yields null rather than an inferred guarantee. A base advertising the feature with missing or malformed epoch fails the prompt operation. Root and native owners advance their own semantic epochs only for their respective result-affecting changes. Notifier adoption and the separate unavailable-task diagnosis are outside this slice.

This is one additive native minor release, 1.33.0 to 1.34.0, through supported synchronization. It changes capability metadata and maintenance guidance only: no prompt normalization, candidate output, cursor epoch, cache schema, provider configuration, hooks, services, GUI or live provider writes.
