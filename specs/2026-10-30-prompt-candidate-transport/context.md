# Context and evidence

The coordinator profiled configured plain ccmsg reads on a stable 227,902,375-byte Codex carrier: initial reads took 2.87–2.89 seconds, of which full normalized dump plus JSON transfer/decode took 1.41–1.49 seconds. Native process time was 1.11–1.19 seconds, output reading 0.10–0.11 seconds, and JSON parsing 0.183–0.186 seconds. Two complete source hashes cost 0.37–0.40 seconds; shared projection cost only 10–18 milliseconds. Smaller 5.8 MB Codex and 3.5 MB Claude reads took about 1.2–1.3 seconds. These separate boundaries motivate narrower transport through complete existing normalization without weakening integrity checks or duplicating cleanup.

The base's `load_provider_messages` already performs provider-neutral tool merging, complete-vector reference collision invalidation and inference hydration. ccmsg then validates reference envelopes and counts collisions by scheme and ID before projecting the conversation. A narrowed command must retain that complete-history invalidation, including collisions against omitted steer or other records, while preserving unreferenced and duplicate candidates so downstream verdicts do not change. Current native references normally use fixed version/session envelopes, but parity is defined against the consumer validator, including UTF-16 length and ECMAScript trim semantics.

Repository instructions and the current committed Claude identity slice establish the normalization/capability boundaries. Harness-kit tooling remains unavailable; this specification follows the existing three-file structure directly. All automated native tests use the supported temporary-profile Rust runner. No native model turn, live hook, notification or service/configuration change belongs to this backend subtask; release replacement is explicitly coordinated by the parent.

Independent review found and verified the correction for separated empty output values before provider work; it reported no remaining code findings. No provider parser or finalizer changed.
