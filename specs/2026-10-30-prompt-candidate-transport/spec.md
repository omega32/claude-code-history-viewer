# Prompt candidate transport

Add headless API v1 command `--dump-session-prompt-candidates <absolute-carrier-path|canonical-session-uuid> --provider <codex|claude> --task-id <canonical-uuid> [--task-id <canonical-uuid> ...] [--format json] [--output <new-file>]`, advertised by command name and feature `prompt-candidates-v1`. Require one to eight distinct complete lowercase canonical task UUIDs and one explicit supported provider. Reject missing, empty, repeated singleton, unknown, conflicting, malformed or excessive arguments before provider work; session prefixes and provider URI selectors are unsupported. Output uses atomic create-new semantics and never replaces an existing path.

Reuse the complete ordinary provider load and finalization without changing parsing, ancestry, authored classification, stable identity, metadata or snapshot contracts. Before omitting any record, count every valid stable reference in the complete finalized vector by `(scheme,id)` and clear all colliding references. Reference validity matches ccmsg's `parseStableRecordRef`: version 1, session scope, bounded ASCII scheme grammar, nonblank ECMAScript-trimmed ID with at most 512 UTF-16 code units and no C0 or DEL controls. Invalid envelopes do not collide with valid references.

Return a bare array containing the unchanged normalized `type:"user"` records whose structured binding matches any requested task ID: Codex requires `subtype:"authored_user"` and `data.providerTurnId`; Claude requires `data.providerPromptId`. Preserve source order, duplicate bindings, missing or invalid references, sidechain flags, metadata and verbatim content. The consumer still applies its shared projection, cleanup, sidechain policy and ambiguity/unavailability decisions. Do not add a narrower content cutoff, select by text, infer identity or return cleaned prompt strings.

Ordinary dump, snapshot, backup, listing, provider normalization, lifecycle control and native hooks remain unchanged. The consumer retains metadata checks and both before/after source and parser-image hashes, gates this transport on both the command and feature, and falls back to the ordinary full dump for an older base. This slice removes unnecessary normalized JSON serialization and transfer, not complete provider replay.
