# Claude native prompt correlation

Expose additive `data.providerPromptId` only for a certified ordinary Claude authored-user record whose native top-level `promptId` is a complete canonical UUID and whose native `promptSource` is exactly `user` or `sdk`. This is the provider's prompt correlation identifier, distinct from the native message `uuid`; it is content correlation and grants no lifecycle or control authority. Preserve ordinary normalized content, existing record identities and unrelated metadata when the new proof is absent, malformed or unsupported.

The headless API remains version 1 and advertises `claude-prompt-id-v1`. Consumers must require both this feature and the existing certified record reference. Missing or unfamiliar prompt source, non-string/malformed optional fields, compaction, interruption, task notifications, local/queued commands, tool-result users and sidechains supply no binding. Raw `data.providerPromptId` cannot impersonate provider proof and is removed before any certified field is attached. Existing non-null scalar/array data remains opaque and cannot receive proof; normalized absence, including raw null under the existing optional-data model, permits a new proof object. Multiple ordinary records may retain the same prompt binding; downstream consumers must reject ambiguous initiating selection rather than choosing the first record.

Claude snapshot cursor version 3 invalidates retained prefixes normalized under version 2. Full and incremental normalization use the same parser. Listing and metadata cache facts are unchanged, and no metadata cache revision is required. Hermes, Codex, lifecycle classification, provider configuration, native hooks and GUI behavior remain outside this change.
