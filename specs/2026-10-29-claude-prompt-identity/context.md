# Context and evidence

This is the Claude extension of ccmsg's exact initiating-prompt read API. The installed Claude Code executable reports `2.1.312`. The [official hook common-input contract](https://code.claude.com/docs/en/hooks#common-input-fields) identifies `prompt_id` as the prompt UUID shared across subsequent events and warns that transcript writes are asynchronous. Read-only inspection of two retained native carriers confirmed top-level `promptId` on user/tool-result records, different from each record's `uuid`, and explicit `promptSource:"sdk"` on ordinary initiating inputs. The binding therefore requires positive native source provenance rather than treating every user-role row as an initiating prompt. Missing-source ordinary records can share a prompt ID with other records and remain unbound.

The existing parser certifies ordinary authored input through `recordRef.scheme:"claude-message"`; it already excludes tools, task notifications, interruptions, command envelopes and compaction. Its structured `data` projection is shared by complete reads and Claude incremental snapshots. The new proof does not replace that message identity or infer a prompt from text, time, counters or UUID equality. Unrelated existing object metadata must survive, while a raw reserved proof property cannot survive without native evidence.

Harness-kit commands are unavailable in this environment; these files follow the repository's existing specification structure directly. All automated provider tests use temporary stores through `pnpm test:rust`; no native model turn, production hook, notification or live profile write is authorized for this subtask.

The tests-first parser gate failed on all four new cases before implementation. The focused implemented `prompt_id` gate passed all five parser/snapshot cases. After the supported version synchronization, the final serial isolated `pnpm test:rust` gate compiled version `1.30.0` and exited successfully: 1,150 library tests and 10 integration tests passed, with nine explicitly ignored live-profile diagnostics. Both `pnpm test:rust clippy` and native `cargo clippy --all-targets --all-features -- -D warnings` passed, as did `cargo fmt --all -- --check` and `git diff --check`. An independent read-only review found no actionable defect in native certification, reserved-property sanitization or cursor invalidation. These synthetic and source checks do not establish native hook delivery or end-to-end prompt lookup acceptance.
